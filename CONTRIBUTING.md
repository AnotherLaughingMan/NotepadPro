# Contributing to Notepad Pro

Thanks for your interest in contributing to Notepad Pro! We welcome bug reports, feature requests, documentation improvements, and code contributions. This document explains how to contribute in a way that helps maintainers review and merge your work quickly.

## Code of Conduct
Please follow our Code of Conduct in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Respectful, constructive interactions make this project welcoming for everyone.

## Ways to Contribute
- Report bugs and suggest features by opening an issue.
- Submit a pull request to propose code or documentation changes.
- Improve docs, examples, and tests.

## Filing Issues
- Use issues to report bugs or request features.
- Provide a clear title and a short description of the problem or idea.
- For bug reports, include:
  - Steps to reproduce
  - Expected behavior
  - Actual behavior
  - Relevant environment (OS, Notepad Pro version, steps taken)
  - Minimal reproducer, if possible

## Pull Request Process
1. Fork the repository and create a branch with a clear name (e.g., `feature/auto-save`, `fix/typo-in-readme`).
2. Keep changes small and focused—one logical change per PR.
3. Update or add tests for any behavioral changes.
4. Run the build locally and ensure tests pass.
5. Rebase or merge from `main` to resolve conflicts before requesting a review.
6. Provide a descriptive PR title and summary explaining why the change is needed and how it was implemented.

## Coding Guidelines
- Follow existing project style and conventions.
- Keep methods and classes focused; prefer small, well-named functions.
- Prefer clarity over cleverness.
- Use meaningful variable and method names.
- Add unit tests for new functionality where practical.

## Commit Messages
- Use present-tense, short summary lines (50 characters max recommended).
- Include a longer description in the body when needed to explain the rationale.

## Testing
- Run the local build and available test suites before opening a PR.
- Where applicable, add tests to cover new behavior or bug fixes.

## Review Process
- Maintainers will review pull requests and may request changes.
- Be responsive to review comments; iterate on the branch as needed.
- Once approved, a maintainer will merge the PR.

## License and Contributor Agreement
By contributing, you agree that your contributions will be licensed under the project's license (see LICENSE). If a Contributor License Agreement (CLA) is required, the repository will include instructions.

## Where to Ask Questions
- Open an issue with the `question` tag, or reach out via the project discussion channels if available.

## Thank You
We appreciate your contributions—big or small. They help make Notepad Pro better for everyone.
